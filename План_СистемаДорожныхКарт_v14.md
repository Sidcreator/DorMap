## 1. Архитектура

### 1.1. Компоненты

| Компонент | Файл | Назначение |
|-----------|------|------------|
| **Единый список проектов** | `projects.json` | Список всех проектов, единый источник истины |
| **Задачи проекта** | `N-проект/tasks.json` | Задачи проекта, единый источник истины |
| **Дорожная карта (сводка)** | `ДорожнаяКарта.md` | Единая сводка по всем проектам |
| **Дорожная карта (проект)** | `N-проект/ДорожнаяКарта.md` | Детализация задач проекта (представление) |
| **Правила дорожной карты** | `ПравилаДорожнойКарты.md` | Полное руководство по работе с дорожной картой |
| **Правила отчётов API** | `ПравилаФормированияОтчетов_API.md` | Правила оформления API-отчётов |
| **Правила AI** | `.clinerules` (корень рабочей области) | Обязательные правила для ИИ-ассистента |
| **Контекст проекта** | `CONTEXT.md` (корень рабочей области) | Сжатое описание проекта и окружения |

| **Журнал изменений** | `N-проект/ЖурналИзменений.md` | История изменений проекта |

### 1.2. Единый источник проектов: `projects.json`

Список всех проектов в корне `ДорожнаяКарта/`. Формат:

```json
{
  "version": 1,
  "defaultProject": "76",
  "activeProject": "КОРП",
  "projects": [
    {
      "id": 1,
      "name": "76",
      "fullName": "1. 76",
      "path": "D:\\1c\\EDT КОРП УОТ\\76",
      "roadmapDir": "1-76",
      "roadmapFile": "1-76/ДорожнаяКарта.md",
      "commands": ["проект 76", "проект 1", "пр76", "пр1"]
    }
  ]
}
```

Поля проекта:
- `id` — номер проекта (1, 2, 3...)
- `name` — короткое имя для команд
- `fullName` — полное имя с номером для отображения
- `path` — полный путь к папке проекта в файловой системе
- `roadmapDir` — имя подпапки в `ДорожнаяКарта/`
- `roadmapFile` — путь к файлу дорожной карты проекта
- `commands` — список команд для переключения проекта

Служебные поля корня:
- `defaultProject` — проект по умолчанию (используется, если `activeProject` не задан)
- `activeProject` — проект, выбранный в сессии; обновляется командой `проект N`

**Правила:**
- Все изменения списка проектов — только в `projects.json`
- **Контекст проекта и расхождение:** при начале сессии и при выполнении команд ИИ сверяет проект, выбранный в сессии (команда `проект N`), с `projects.json.activeProject` (если поля нет — с `defaultProject`). При расхождении ИИ **сообщает об этом пользователю** и **переключает контекст на проект, выбранный в сессии** (выбор в сессии — приоритетный). Команда `проект N` записывает выбор в `projects.json.activeProject`.

### 1.3. Единый источник задач: `tasks.json`

Каждый проект имеет `tasks.json` в своей папке `ДорожнаяКарта/N-проект/`. Структура задачи:

```json
{
  "id": 1,
  "name": "Название задачи",
  "priority": "P2",
  "complexity": 2,
  "progress": 0,
  "section": "active",
  "start": "2026-06-25",
  "end": null,
  "time_min": null,
  "stages": [
    { "id": "1.1", "name": "Этап", "desc": "Описание", "status": "⬜", "date": null, "report": "отчеты/Отчет_1.1_Описание.html" }
  ]
}
```

Поля:
- `section` — `"active"` / `"done"` / `"completed"` / `"postponed"` / `"unplanned"`
- `unplanned` — `true` для неплановых задач (маркер категории «Неплан»)
- `reason` — причина откладывания (для `postponed`)
- `stages[].status` — `⬜` (не начат), `🔵` (в работе), `✅` (выполнен), `🧪` (тестирование), `⚠️` (проблема), `🔒` (заблокирован), `⏭️` (пропущен)
- `stages[].report` — путь к HTML-отчёту **относительно корня** `ДорожнаяКарта/` (например, `отчеты/Отчет_12.1_...html`)
- Для `done` задач: `start`, `end`, `time_min` заполнены
- Для `postponed`: поле `reason`

**Категория «Неплан» (`section: unplanned`):**
- Задачи, появившиеся вне дорожной карты (внешний запрос, разбор инцидента, справочные материалы)
- Поле `"unplanned": true` — маркер в `tasks.json`
- **Нет лимита 10 активных задач** — неплановые не считаются в лимит
- Отображаются отдельной таблицей `🆕 Неплан — {fullName}`
- При закрытии переносятся в `section: done` (флаг `unplanned` сохраняется для истории)
- Статус-эмодзи: 🆕

**Workflow:**
1. Все изменения задач вносятся только в `tasks.json`
2. После изменения AI перегенерирует `ДорожнаяКарта.md` проекта
3. Команда `др` строит сводку из `tasks.json` (не из `.md`)
4. При любом изменении дорожной карты — регенерировать `отчеты/ДорожнаяКарта.html` (скрипт `sync_roadmap.py`)

### 1.4. Структура папок

```
ДорожнаяКарта/                          ← корень системы
├── projects.json                       ← единый список проектов (источник истины)
├── ДорожнаяКарта.md                    ← единая сводка (все проекты)

│   ├── ДорожнаяКарта.html              ← единый HTML-отчёт дорожной карты
│   └── Отчет_N.N_*.html                ← отчёты этапов всех проектов
```

## 2. Структура нумерации

| Уровень | Формат | Пример | Описание |
|---------|--------|--------|----------|
| 1 (задача) | `N` | `1` | Крупная задача |
| 2 (этап) | `N.N` | `1.1` | Стадия выполнения |
| 3 (шаг) | `N.N.N` | `1.2.1` | Конкретное действие |

Правила нумерации:
- Номера задач — последовательно, следующий свободный
- Активные задачи: 1, 2, 3... (максимум 10)
- Выполненные: группируются под одной задачей (напр. 7)
- Отложенные: группируются под одной задачей (напр. 8)
- При переносе из выполненных/отложенных в активные — новый активный номер

## 4. Команды управления

> Все команды вводятся в чат AI-ассистента. AI автоматически определяет команду по ключевой фразе.

| Категория | Команда | Действие |
|-----------|---------|----------|
| **Просмотр** | `др` / `др1` / `сводка` / `итого` / `дорожная карта` | Сводка **всех 3 проектов** (активные ▶ + ✅ + ⏸️ + 🆕 неплан) |
| | `др2` / `дор карта 2` | Детализация текущего проекта |
| | `проект N` / `прN` | Переключиться на проект N (и записать его в `projects.json.activeProject`) |
| | `стз N` / `статус задачи N` | Детализация задачи N в текущем проекте |
| **Управление** | `заводим задачу` | Создать задачу (макс 10 активных) |
| | `заводим неплановую задачу` / `неплан` | Создать задачу в категории «Неплан» (без лимита 10) |
| | `обнови статус N.M` | Изменить статус этапа |
| | `закрываем задачу N` | ✅ Пометить готово, запросить время |
| | `откладываем задачу N` | ⏸️ Отложить с причиной |
| | `верни задачу N в активные` | Вернуть из выполненных/отложенных в активные с новым номером |
| **Время** | `затрачено N мин на задачу M` | Вписать время |
| | `итого время` | Сводка времени |
| **Отчёты** | `отк отчет` / `отк от` | Открыть последний отчёт |
| | `отк отчет ИмяФайла` | Открыть по имени |
| | `отк отчет N.N` | Открыть по этапу |
| | `обнови отчет дорожной карты в html` | Регенерировать `отчеты/ДорожнаяКарта.html` из `tasks.json` (`sync_roadmap.py`) |
| **Правила** | `правила дорожной карты` | Показать `ПравилаДорожнойКарты.md` |
| | `обновить правила дорожной карты` | Создать новую версию плана |
| | `синхронизация` | Синхронизировать проекты |

### Контекст проекта и расхождение с projects.json

- При начале сессии и при выполнении команд ИИ сверяет проект, выбранный в сессии (команда `проект N`), с `projects.json.activeProject` (если поля нет — с `defaultProject`).
- При расхождении ИИ **сообщает об этом пользователю** и **переключает контекст на проект, выбранный в сессии** (выбор в сессии — приоритетный).
- Команда `проект N` обновляет `projects.json.activeProject` — следующая сессия стартует с верного проекта, расхождение не повторяется.

## 5. Конвенции

### 5.1. Лимит активных задач
- Максимум **10 активных задач** одновременно
- При создании 11-й — авто-отложить с причиной
- **Неплановые задачи (`section: unplanned`) не считаются в лимит 10** — создаются свободно

### 5.2. Учёт времени в минутах
- Единица измерения: минуты (целое число)
- При старте задачи/этапа: `—` (прочерк)
- При завершении: вписать количество минут (например: `15`, `120`, `5`)
- При промежуточном статусе: `~N мин` (приблизительная оценка)
- Итог по времени: `N мин` или `N ч M мин` при N ≥ 60
- При закрытии задачи AI автоматически запрашивает затраченное время

### 5.3. Именование файлов
- **Вспомогательные файлы** (планы, инструкции, changelog) — с суффиксом `_vN`
- **Основные рабочие файлы** — без суффикса: `ДорожнаяКарта.md`, `ПравилаДорожнойКарты.md`, `README.md`, `projects.json`, `tasks.json`
- Имена папок проектов: `N-КороткоеИмя` (например, `1-76`, `2-76_in_КОРП`)
- Имя HTML-отчёта: `Отчет_N.N_КраткоеОписание.html`

### 5.4. Кодировка
- `tasks.json` — только UTF-8
- При генерации HTML обязательны `fix()` (`s.encode('cp1251').decode('utf-8')` — устранение двойной кодировки `UTF8→CP1251→UTF8` типа `d0a0→d090` «Р»→«А») и `html.escape` для `&<>` в `name/desc`

### 5.5. Единая папка отчётов
- Все HTML-отчёты хранятся в **единой корневой папке** `ДорожнаяКарта/отчеты/`, независимо от проекта
- Путь в `tasks.json` (поле `report`) указывается относительно корня: `"report": "отчеты/Отчет_N.N_Описание.html"`
- Проектные папки (`1-76/отчеты/`, `2-76_in_КОРП/отчеты/`, `3-КОРП/отчеты/`) **не используются**

### 5.6. Единый отчёт дорожной карты (HTML)
- Формируется по образцу `отчеты/Отчет_ДорожнаяКарта_все_проекты.html` (стили, вёрстка, структура)
- Имя файла: `отчеты/ДорожнаяКарта.html`
- Содержит: сводную таблицу всех проектов, активные/выполненные/отложенные/неплановые задачи с progress-барами, детализацию этапов
- **Гиперссылки:** каждая задача в сводной таблице — ссылка на детализацию ниже (и номер, и название задачи)
- Генерируется скриптом `sync_roadmap.py` из `tasks.json`
- Команда: `обнови отчет дорожной карты в html`
- При любом изменении дорожной карты — обновлять `ДорожнаяКарта.html`

### 5.7. План версии — полное описание
- `План_СистемаДорожныхКарт_vN.md` — самодостаточный документ для развёртывания с нуля
- Должен содержать **полную спецификацию**: архитектуру, все правила, команды, конвенции, форматы, лимиты. Не только изменения
- AI, получив этот файл, должен иметь достаточно информации, чтобы создать все файлы системы без обращения к другим источникам

## 6. Формат таблиц

### Сводная таблица задач (уровень 1)

```
| № | Задача | P | Сложность | % | Статус | Начало | Конец | Время (мин) |
```

### Таблица этапов (уровень 2, для команд `стз N`)

```
| Этап | Название | Статус | Отчёт |
```

Примечание: колонка «Статус» идёт ПОСЛЕ «Название».

### Таблица отложенных

```
| № | Задача | Причина | P | Дата |
```

`Причина = tasks.json:reason`.

### Таблица неплановых

Колонки как у активных: `№ | Задача | P | Сложность | % | Статус | Начало | Конец | Время (мин)`.

### Обязательное разделение таблиц

Активные, выполненные, отложенные и неплановые задачи — в **разных таблицах** (не сводной). Заголовки:
- `▶ Активные задачи — {fullName}`
- `✅ Выполнено — {fullName}`

### 7.3 Обязательные элементы

#### `.meta` — шапка отчёта
```
<div class="meta">
<span><strong>Этап:</strong> N.N</span>
<span><strong>Задача:</strong> N. Название задачи</span>
<span><strong>Дата:</strong> ГГГГ-ММ-ДД</span>
<span><strong>Статус:</strong> <span class="ok">текст</span></span>
</div>
```
Номер этапа (N.N) в `.meta` должен **строго совпадать** с именем файла и с `id` этапа в `tasks.json`.

#### `<title>` — заголовок вкладки
Содержит номер этапа: `Отчет N.N — ...` или `... N.N ...`.

#### `.toc` — содержание
Пункты ссылаются на якоря `<h2 id="section-id">`. Вёрстка: пункты в строку (`ol {display:flex; flex-wrap:wrap;}`).

#### Якоря разделов
`<h2 id="section-id">N. Название раздела</h2>` — `id` латиницей, дефисы вместо пробелов.

#### Навигация «↑ к содержанию»
После каждой таблицы и логического блока: `<div class="back"><a href="#top">↑ к содержанию</a></div>`.

#### Блоки callout
- `.callout-issue` — критическая проблема (красный)
- `.callout-warn` — предупреждение (оранжевый)
- `.callout-ok` — успех (зелёный)
- `.callout-premium` — требование подписки (синий)

#### Подвал (footer)
```
<footer>
Отчёт создан: ГГГГ-ММ-ДД | Проект X/N, задача N, этап N.N | ...
</footer>
```

### 7.4 JSON в `<pre>`
Подсветка синтаксиса через span-классы: `.key`, `.str`, `.num`, `.bool`.

### 7.5 Якоря для методов API
- `<h2 id="method--endpoint-name">` — латиница, слеши заменяются на дефисы
- Пример: `<h2 id="method--v2-reports-shows-sales-generate">`

### 7.6 Матрица методов (сводная таблица)
Колонки: `# | Метод API | HTTP | Тип | Статус в УОТ614 | Приоритет | Отчёт`. Эндпоинты — ссылки на якоря `#method--...`; статус — через `.ok` / `.warn` / `.issue`.

### 7.7 Итоговая статистика
В конце отчёта — таблица-сводка `<h3>Итоговая статистика</h3>` (Параметр | Значение).

### 7.8 Рабочий процесс (Workflow)
Для многошаговых lifecycle — секция с нумерованным списком шагов в `<pre>`:
```
1. POST /v2/reports/generate
2. GET /v2/reports/info/{reportId}  (цикл опроса)
3. GET {url}  (скачивание)
4. Парсинг JSON → регистры/документы
```
Шаги нумеруются `1.`, `2.`, `3.`; стрелка `→` для результата шага; комментарии в скобках.

### 7.9 Внутренние якоря в самодостаточном отчёте
Сводный отчёт самодостаточен — ссылки на внешние HTML-файлы не используются. Каждая секция метода API имеет `id` вида `id="префикс-короткое-имя"` (префикс — код МП: `wb`, `ozon`, `yam`).

### 7.10 Гиперссылки на методы API
В матрицах методов название метода — гиперссылка на внутренний якорь в этом же отчёте. Внешние ссылки (`href="Отчет_...html#..."`) должны отсутствовать.

## 10. Версионирование планов

### Правила
1. Файл плана всегда содержит версию в названии: `План_СистемаДорожныхКарт_vN.md` (N = номер версии)
2. Актуальная версия — файл с наибольшим номером N
3. При значительных изменениях:
   - Создать новый файл `План_СистемаДорожныхКарт_v(N+1).md` — **полное описание**, а не только изменения
   - Предыдущий файл остаётся без изменений (естественный архив)
4. Журнал версий — таблица в начале файла с колонками: Версия, Дата, Сессия, Изменения
5. Связь план↔карта: при каждом изменении плана проверять соответствие с `ДорожнаяКарта.md`

### Когда создавать новую версию

| Событие | Действие |
|---------|----------|
| Добавлен новый статус/символ | Новый файл v(N+1) |
| Изменена структура таблиц | Новый файл v(N+1) |
| Добавлена новая ключевая фраза | Новый файл v(N+1) |
| Изменён формат учёта времени | Новый файл v(N+1) |
| Изменена конвенция именования файлов | Новый файл v(N+1) |
| Добавлена новая категория команд | Новый файл v(N+1) |
| Добавлена новая колонка в таблицы | Новый файл v(N+1) |
| Добавлены новые папки/структура | Новый файл v(N+1) |
| Исправление опечатки | Без нового файла |
| Обновление примеров | Без нового файла |

### Правило синхронизации проектов
При любом изменении правил дорожной карты изменения применяются ко **всем проектам**:
- `1-76/ДорожнаяКарта.md`, `2-76_in_КОРП/ДорожнаяКарта.md`, `3-КОРП/ДорожнаяКарта.md`

## 15. Правила формирования отчёта API-методов маркетплейса

> Версия: 1.0 (2026-07-10) · Источник: анализ `Отчёт_API_Методы_Ozon_УОТ609_vs_УОТКОРП.md`

### 15.1. Источники данных

Для каждого МП проверяются **4 группы источников**:

#### 15.1.1. Код базовой поставки (УОТ76 / УОТ611)

| Что | Где | Что ищется |
|-----|-----|-----------|
| ObjectModule.bsl | `DataProcessors/CG_Online_{MP}_ИнтеграцияС{Сервис}/Ext/ObjectModule.bsl` | `Метод = "vX/..."` |
| CommonModule (если есть) | `CommonModules/CG_Online_{MP}_ИнтеграцияС{Сервис}/Ext/Module.bsl` | `Метод = "vX/..."` |

#### 15.1.2. Код КОРП-поставки (УОТКОРП)

| Что | Где | Что ищется |
|-----|-----|-----------|
| CommonModule.bsl | `CommonModules/CG_Online_{MP}_ИнтеграцияС{Сервис}/Ext/Module.bsl` | `Метод = "vX/..."` |
| ObjectModule.bsl | `DataProcessors/CG_Online_{MP}_ИнтеграцияС{Сервис}/Ext/ObjectModule.bsl` | `Метод = "vX/..."` |

> **Важно:** В УОТКОРП CM и OM **дублируют** друг друга (lockstep). Проверка делается раздельно, чтобы зафиксировать расхождения в версиях API между CM и OM (например, CM использует v6, а OM — v5).

#### 15.1.3. Тестовое расширение базовой поставки (76тест)

| Что | Где | Что ищется |
|-----|-----|-----------|
| Переопределяемый модуль | `CommonModules/CG_Online_UT_ИнтеграцииССервисами{MP}Переопределяемый/Ext/Module.bsl` | Строки эндпоинтов `"vX/..."` в функциях-заглушках/моках |
| Макеты-фикстуры (JSON) | `CommonTemplates/CG_Online_{MP}_JSON_*` | Имена макетов содержат эндпоинты |

> **Архитектура 76тест:** макеты хранятся в CommonTemplates (плоская структура, ~504 шт), моки — в переопределяемых модулях.

#### 15.1.4. Тестовое расширение КОРП-поставки (КОРПтест)

| Что | Где | Что ищется |
|-----|-----|-----------|
| ManagerModule.bsl | `DataProcessors/CG_Online_UT_{MP}_ИнтеграцияС{Сервис}/Ext/ManagerModule.bsl` | Строки эндпоинтов `"vX/..."` в моках |
| ObjectModule.bsl | `DataProcessors/CG_Online_UT_{MP}_ИнтеграцияС{Сервис}/Ext/ObjectModule.bsl` | Дополнительные моки |
| Макеты внутри обработки | `DataProcessors/CG_Online_UT_{MP}_.../Templates/` | Имена макетов |

> **Архитектура КОРПтест:** макеты хранятся внутри DataProcessors по каждому МП (модульная структура, 24+ обработок).

### 15.2. Методология проверки

#### Поиск эндпоинтов в коде
Для каждого BSL-файла ищутся строки вида `Метод = "v1/product/list";`. Результат: список уникальных API-эндпоинтов с отметкой, в каком модуле найден (CM или OM), и строкой.

#### Статус активности

| Признак | Статус | Обозначение в таблице |
|---------|--------|----------------------|
| Код активен, есть HTTP-вызов | Активен | ✅ |
| Код закомментирован (`// Метод = "..."` или `// код из 76...`) | Закомментирован | `✅ (коммент.)` |
| Только URL в строке-комментарии | Неактивен | `✅ (коммент.)` |

#### Определение статуса сравнения

| Статус | Условие | Символ |
|--------|--------|--------|
| **Совпадает** | Один и тот же эндпоинт и версия в УОТ76 и УОТКОРП | ✅ Совпадает |
| **Перенесено** | Есть в УОТ76, есть в УОТКОРП, но только в CM (не в OM) или наоборот | 🔵 Перенесено |
| **Разные версии** | Один эндпоинт, но разные версии API (v1 vs v2, v3 vs v2) | ⚠️ Разные версии |
| **Неактивен** | Закомментирован в обоих расширениях | 💤 Неактивен |
| **Отсутствует** | Есть в УОТ76, отсутствует в УОТКОРП (реально) | 🔴 Отсутствует |

#### Определение покрытия тестами
Эндпоинт считается **покрытым тестами**, если:
- В 76тест: строка эндпоинта встречается в переопределяемом модуле (функция-заглушка возвращает JSON-макет)
- В КОРПтест: строка эндпоинта встречается в ManagerModule.bsl (мокито-перехват)

> **Не считается покрытием:** простое наличие макета с похожим именем без явной привязки к эндпоинту в коде теста.

#### Сравнение макетов (колонка «Макет КОРП = 76»)
Сравнивается **содержимое** макетов (файлы Template.txt/Template.xml) между КОРПтест и 76тест:

| Значение | Условие |
|----------|---------|
| `✅ да` | Файлы идентичны побайтово (`fc /b` = 0 различий) |
| `частично` | Идентичны не все — есть различия |
| `нет` | Макеты существуют, но различаются |
| `—` | Макетов нет ни в одном из тестовых расширений, или эндпоинт не покрыт тестами |

> **Важно:** сравнивается только содержимое (Template.txt), а не логика доступа к макетам (`ПолучитьМакет` vs `ПолучитьОбщийМакет`).

**Яндекс.Маркет (ЯМ):** OAuth 2.0 авторизация; разные домены для разных API-групп; GET + POST + PUT + PATCH.
