```json
      "id": 1,
      "name": "ProjectA",
```

## 2. Нумерация

### 2.1. ID задачи — глобальный якорь

- **Глобальная сквозная нумерация** 1..N на всю дорожную карту, все проекты
- Выдаётся только через `id_registry.json` (`nextId`), генератор — `new_task.py`
- **Не меняется никогда**; не переиспользуется (retired); старый ID — в `legacyId`
- Порядок выдачи при миграции: проекты по `projects.json`, внутри — числовые по возрастанию, затем легаси (completed, затем postponed)

### 2.2. Этапы

`<ID>.<M>` (M неизменяем; новый этап — следующий свободный M). Допустим шаг `<ID>.<M>.<K>`.

### 2.3. № в разделе

Вычисляется 1..N внутри раздела по возрастанию ID; без пропусков; не хранится; при переносе пересчитывается; отображается колонкой `№` рядом с `ID`.

### 2.4. История задачи (`history[]`)

Append-only. События: `created`, `section`, `stage`, `progress`, `report`, `migrated`, `renamed`, `decision`, `note`. Поля: `date`, `event`, `stage`, `from`, `to`, `note`. Любое изменение фиксируется; старые записи не правятся.

**Обязательно:** привязка/замена/переименование отчёта фиксируется событием `report`:
```json
{ "date": "ГГГГ-ММ-ДД", "event": "report", "stage": "7.1", "to": "отчеты/Отчет_7_1.1_Описание.html", "note": "отчёт привязан к этапу" }
```
События `report` выводятся в журнале и в блоке истории отчёта наравне с остальными.

### 2.5. ID-реестр (`id_registry.json`)

```json
{ "version": 1, "nextId": 8,
  "allocations": [ {"id": 1, "project": "ProjectA", "legacyId": "1", "task": "...", "date": "ГГГГ-ММ-ДД", "reason": "migrated"} ] }
```
`allocations` — append-only; `nextId` инкрементируется генератором; валидатор сверяет задачи ↔ реестр.

## 5. Конвенции

### Лимит активных задач
Максимум 10 активных; при 11-й — авто-отложить с причиной; неплановые не считаются.

### Учёт времени
Минуты (целое); `—` при старте, `N` при завершении, `~N` промежуточно.

### Именование файлов
- Вспомогательные — `_vN`; основные — без суффикса
- Отчёт (F2): `<Тип>_<ID>_<№>.<M>_КраткоеОписание.html` (Тип: Отчет/План/Протокол)
- Пример: `Отчет_7_1.1_КраткоеОписание.html`

### Перенос задачи и переименование отчётов
- Меняется только `section`; ID не меняется; № пересчитывается
- Все отчёты этапов переименовываются под новый №; обновляются `.meta`, `<title>`, строки идентификации, поле `report`
- В `history`: `section` (from→to), `renamed` (from→to)

### Кодировка
`tasks.json` — UTF-8. В генераторах обязательны `fix()` (двойная кодировка) и `html.escape`.

### Папка отчётов
Единая `ДорожнаяКарта/отчеты/`; путь в `tasks.json` — `отчеты/<файл>`; проектные папки отчётов не используются.

**Ссылки на отчёты:**
- в `отчеты/ДорожнаяКарта.html` (лежит в той же папке) — только имя файла: `href="Отчет_<ID>_<№>.<M>_…html"`
- в проектных `N-проект/ДорожнаяКарта.md` — `[имя](../отчеты/Отчет_<ID>_<№>.<M>_….html)`
- абсолютные/удвоенные пути (`отчеты/отчеты/…`) запрещены

### Журнал изменений
Генерируется из `history[]`; содержит ID, этап, дату, событие, было→стало, основание; при миграции — карту old→new ID.

## 7. Формат HTML-отчёта

### 7.1. Идентификация (обязательно)
- Вверху (после `<h1>`) и внизу (перед `</body>`):
```html
<div class="project">Проект {id}. {fullName}</div>
<div class="project-id">Задача ID {ID} · №{№} · Этап {ID}.{M}</div>
```
- Проект — **средним шрифтом**: `.project { font-size: 15px; font-weight: 600; }`

### 7.2. `.meta`
```html
<div class="meta">
<span><strong>Задача:</strong> ID {ID} (№{№} в разделе)</span>
<span><strong>Этап:</strong> {ID}.{M}</span>
<span><strong>Дата:</strong> ГГГГ-ММ-ДД</span>
<span><strong>Статус:</strong> <span class="ok">текст</span></span>
</div>
```

### 7.3. Обязательные элементы
`.toc` (пункты в строку), якоря `<h2 id="...">`, навигация `<div class="back"><a href="#top">↑ к содержанию</a></div>`, callout-блоки, footer с ID+№+проектом.

### 7.4. История в отчёте
```html
<!-- HISTORY:START -->
<h2 id="history">История задачи</h2>
<p><strong>Создана:</strong> … · <strong>Статус:</strong> … · <strong>Событий:</strong> … · <strong>Последнее:</strong> …</p>
<table>
<tr><th>Дата</th><th>Событие</th><th>Этап</th><th>Было → Стало</th><th>Основание</th></tr>
...
</table>
<!-- HISTORY:END -->
```
Блок регенерируется; ручной текст вне маркеров не затирается.

## 10. Версионирование планов

- `План_СистемаДорожныхКарт_vN.md` — полная самодостаточная спецификация (а не только изменения)
- Предыдущая версия не изменяется (архив); актуальная — файл с наибольшим N
- Журнал версий — таблица в начале файла (строка `| **vN** |`)

### 10.1. Триггеры создания новой версии

| Триггер | Пример | Новая версия? |
|---------|--------|---------------|
| Изменение структуры компонентов | Новый скрипт, новый JSON-файл | ✅ Да |
| Изменение формата данных | Новая схема `tasks.json`, новый тип события | ✅ Да |
| Изменение команд | Новая команда, изменение поведения команды | ✅ Да |
| Изменение формата отчёта | Новый CSS-класс, новая секция HTML | ✅ Да |
| Изменение правил нумерации | Новый формат ID, новый тип этапа | ✅ Да |
| Добавление/удаление раздела | Новый §N или удаление §N | ✅ Да |
| Изменение логики скриптов | Новый параметр `new_task.py`, новая проверка | ✅ Да |
| Изменение стилей скриптов | Правка CSS в `sync_roadmap.py` без смены структуры | ❌ Нет |
| Обновление версий зависимостей | Python 3.12 → 3.13 | ❌ Нет |
| Исправление опечаток в документации | Правка текста §1–§15 | ❌ Нет |
| Добавление примеров/комментариев | Новый пример в описании команды | ❌ Нет |

### 10.2. Требования к новой версии (14 пунктов)

Версия считается готовой, только если по ней одной, без обращения к другим файлам, разворачивается полностью рабочая дорожная карта:

1. Встроены все компоненты: `projects.json`, `id_registry.json`, `tasks.json`, `ПравилаДорожнойКарты.md`, `ПравилаФормированияОтчетов_API.md`, `README.md`, `CONTEXT.md`, `.clinerules`
2. Встроен полный код операционных скриптов: `new_task.py`, `sync_roadmap.py`, `validate_roadmap.py`, `check_plan.py`
3. Встроен код миграционных утилит `normalize_ids.py`, `report_history.py` (если применимо)
4. Формат HTML-отчёта: CSS, идентификация (ID + № + проект сверху и снизу), блок истории
5. Правила ссылок на отчёты — без удвоенных путей
6. Раздел «Развёртывание» с единственными правками: `ROOT` в скриптах, пути в `projects.json`
7. Чеклист внедрения и инструкция добавления нового проекта
8. Нет незаполненных маркеров-заглушек (два символа «собака» подряд) и BOM внутри блоков кода
9. Встроенный python-код компилируется, все блоки кода закрыты (чётное число fence-маркеров)
10. Нумерация разделов без дублей; все ссылки вида §N.M существуют
11. Нет внешних зависимостей (кроме исторических ссылок в шапке и журнале версий)
12. Процедура аудита: `check_plan.py` → **PASS** + ручной чек-лист B1–B12, C1–C10
13. План не содержит данных реальных проектов: путей, имён проектов, их отчётов (проверки A31, A32)
14. Есть установщик одним файлом `roadmap_setup.py`, соответствующий коду плана (проверка A33)

### 10.3. Процедура выпуска версии

1. Прочитать текущую версию (наибольший N) и определить триггер по §10.1
2. Создать `План_СистемаДорожныхКарт_v(N+1).md` — полная спецификация, не только изменения
3. Перевстроить код скриптов: `python embed_plan.py` (пути автоматически обезличиваются до `<ROOT>`)
4. Добавить строку `| **v(N+1)** |` в журнал версий и обновить ссылку «Предыдущий файл»
5. Прогнать `python check_plan.py` → **PASS** и ручной чек-лист B1–B12 / C1–C10
6. Приложить вывод аудита к задаче/сообщению

### 10.4. Аудит (обязательно перед публикацией)

- Автоматический: `python check_plan.py План_СистемаДорожныхКарт_vN.md` → **PASS** (A1–A33)
- Ручной: `Чеклист_Самодостаточности_Плана.md` — B1–B12 (самодостаточность), C1–C10 (саморазвёртываемость)
- **Без PASS** версия не публикуется и не используется для развёртывания; при FAIL — исправить и повторить аудит

### 13.6. Скрипты

#### `new_task.py`
```python
import argparse, json, pathlib, datetime, re, sys

ROOT = pathlib.Path(r"<ROOT>")  # ← заменить на путь к папке ДорожнаяКарта
if str(ROOT).startswith("<"):
    raise SystemExit("ERROR: в скрипте не заменён путь <ROOT>")
MAX_ACTIVE = 10


def load_json(path):
    return json.loads(path.read_bytes().decode("utf-8-sig"))


def save_json(path, data):
    path.write_text(json.dumps(data, ensure_ascii=False, indent=2), encoding="utf-8")


def section_group(section):
    if section in ("done", "completed"):
        return "done"
    if section == "postponed":
        return "postponed"
    if section == "unplanned":
        return "unplanned"
    return "active"


def compute_numbers(tasks):
    groups = {"active": [], "done": [], "postponed": [], "unplanned": []}
    for t in tasks:
        groups[section_group(t.get("section"))].append(t.get("id"))
    nums = {}
    for g, ids in groups.items():
        for i, tid in enumerate(sorted(ids), 1):
            nums[tid] = i
    return nums


def main():
    ap = argparse.ArgumentParser(description="Единственный генератор ID и задач дорожной карты")
    ap.add_argument("--project", required=True, help="Имя проекта (например, ProjectA) или его id")
    ap.add_argument("--name", required=True, help="Название задачи")
    ap.add_argument("--priority", default="P2")
    ap.add_argument("--complexity", type=int, default=2)
    ap.add_argument("--desc", default="")
    ap.add_argument("--stages", default="", help="Этапы через ';' (по умолчанию один: Постановка)")
    ap.add_argument("--unplanned", action="store_true", help="Создать в категории Неплан")
    args = ap.parse_args()

    projects_data = load_json(ROOT / "projects.json")
    project = None
    for p in projects_data["projects"]:
        if str(p["name"]).lower() == args.project.lower() or str(p["id"]) == str(args.project):
            project = p
            break
    if project is None:
        print("ERROR: проект не найден:", args.project)
        return 1

    registry = load_json(ROOT / "id_registry.json")
    tasks_file = ROOT / project["roadmapDir"] / "tasks.json"
    data = load_json(tasks_file)
    tasks = data.get("tasks", [])

    today = datetime.date.today().isoformat()
    section = "unplanned" if args.unplanned else "active"
    auto_postponed = False
    if section == "active":
        active_count = len([t for t in tasks if t.get("section") == "active"])
        if active_count >= MAX_ACTIVE:
            section = "postponed"
            auto_postponed = True

    new_id = int(registry["nextId"])
    registry["nextId"] = new_id + 1

    stage_names = [s.strip() for s in args.stages.split(";") if s.strip()] or ["Постановка"]
    stages = []
    for i, nm in enumerate(stage_names, 1):
        stages.append({"id": f"{new_id}.{i}", "name": nm, "desc": "", "status": "⬜"})

    history = [{"date": today, "event": "created", "note": "создана через new_task.py"}]
    if auto_postponed:
        history.append({"date": today, "event": "section", "from": "active", "to": "postponed",
                        "note": f"лимит {MAX_ACTIVE} активных задач"})

    task = {
        "id": new_id,
        "name": args.name,
        "priority": args.priority,
        "complexity": args.complexity,
        "progress": 0,
        "section": section,
        "start": today,
        "end": None,
        "time_min": None,
        "stages": stages,
        "history": history,
    }
    if args.unplanned:
        task["unplanned"] = True
    if args.desc:
        task["desc"] = args.desc

    tasks.append(task)
    tasks.sort(key=lambda t: t.get("id", 0))
    data["tasks"] = tasks
    data["updated"] = today
    save_json(tasks_file, data)

    registry["allocations"].append({
        "id": new_id,
        "project": project["name"],
        "legacyId": None,
        "task": args.name,
        "date": today,
        "reason": "created",
    })
    save_json(ROOT / "id_registry.json", registry)

    nums = compute_numbers(tasks)
    num = nums.get(new_id, "?")
    print(f"CREATED id={new_id} num={num} section={section} project={project['name']}")
    if auto_postponed:
        print("  WARNING: лимит 10 активных — задача создана в разделе postponed")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

#### `sync_roadmap.py`
```python
import pathlib, json, datetime, html, re, sys, argparse


ROOT = pathlib.Path(r"<ROOT>")  # ← заменить на путь к папке ДорожнаяКарта
if str(ROOT).startswith("<"):
    raise SystemExit("ERROR: в скрипте не заменён путь <ROOT>")
WORKSPACE = ROOT.parent
MAX_ACTIVE = 10
RULES_VERSION = "v?"


def extract_section(text, section_header):
    """Извлечь содержимое секции из плана (например, '## 1. Архитектура')."""
    pattern = r"(^" + re.escape(section_header) + r"\s*\n.*?)(?=^## \d+\.\s|\Z)"
    m = re.search(pattern, text, re.M | re.S)
    if m:
        return m.group(1).strip()
    return None


def extract_sections_range(text, start_header, end_header):
    """Извлечь диапазон секций от start_header до end_header (включительно)."""
    pattern = r"(^" + re.escape(start_header) + r"\s*\n.*?)(?=^" + re.escape(end_header) + r")"
    m = re.search(pattern, text, re.M | re.S)
    if m:
        return m.group(1).strip()
    return None


def extract_md_block(text, header):
    """Извлечь первый markdown-блок (в тройных обратных кавычках), следующий за заголовком."""
    fence_marker = "`" * 3
    i = text.find(header)
    if i < 0:
        return None
    fence = text.find(fence_marker + "markdown", i)
    if fence < 0:
        return None
    start = text.find("\n", fence) + 1
    end = text.find("\n" + fence_marker, start)
    if start <= 0 or end < 0:
        return None
    return text[start:end].strip() + "\n"


def detect_rules_version(plan_path):
    """Определить версию правил из плана (строка «Полное руководство (vN)»)."""
    try:
        text = plan_path.read_text(encoding="utf-8")
        m = re.search(r"Полное руководство \(v(\d+)\)", text)
        if m:
            return "v" + m.group(1)
    except Exception:
        pass
    return "v?"


def fill_context_template(content):
    """Подставить реальные значения в шаблон CONTEXT.md."""
    active = ""
    projects_file = ROOT / "projects.json"
    if projects_file.exists():
        try:
            data = json.loads(projects_file.read_bytes().decode("utf-8-sig"))
            active = data.get("activeProject") or data.get("defaultProject", "")
        except Exception:
            active = ""
    return content.replace("<имя>", active).replace("<путь>", str(ROOT.parent))


def generate_rules_from_plan(plan_path, force_docs=False):
    """Сгенерировать правила и шаблоны документов из плана.

    Правила (ПравилаДорожнойКарты.md, ПравилаФормированияОтчетов_API.md) —
    производные файлы, перезаписываются всегда.
    Шаблоны (README.md, .clinerules, CONTEXT.md) — только если файла нет
    или указан force_docs=True (защита ручных правок).
    """
    if not plan_path.exists():
        print("  WARN: план не найден, правила не генерируются")
        return 0
    plan_text = plan_path.read_text(encoding="utf-8")
    generated = 0
    # ПравилаДорожнойКарты.md — §1–§11 (Архитектура … Ограничения)
    rules = extract_sections_range(plan_text, "## 1. Архитектура", "## 12.")
    if rules:
        rules_path = ROOT / "ПравилаДорожнойКарты.md"
        rules_path.write_text(rules, encoding="utf-8")
        generated += 1
        print(f"  OK ПравилаДорожнойКарты.md ({rules_path.stat().st_size} bytes)")
    # ПравилаФормированияОтчетов_API.md — §15

def fix(s):
    if not isinstance(s, str) or not s:
        return s
    if "Рђ" in s or "Р " in s or "РЅ" in s:
        try:
            cand = s.encode("cp1251", errors="ignore").decode("utf-8", errors="ignore")
            if cand != s:
                return cand
        except Exception:
            pass
        try:
            cand2 = s.encode("utf-8", errors="ignore").decode("cp1251", errors="ignore")
            if cand2 != s and "Анализ" in cand2:
                return cand2
        except Exception:
            pass
    return s
```

```python
    if section == "postponed":
        return "postponed"
    if section == "unplanned":
        return "unplanned"
    return "active"


def legacy_sort_key(task):
    sid = str(task.get("id", ""))
    digits = re.sub(r"[^0-9]", "", sid)
    return (int(digits) if digits else 0, sid)


def stage_rest(stage_id, old_task_id):
    sid = str(stage_id)
    prefix = str(old_task_id) + "."
    if sid.startswith(prefix):
        return sid[len(prefix):]
    parts = sid.split(".")
    return parts[-1] if parts else ""


def report_new_name(report, new_id, num, m):
    rel = norm_report_path(report)
    name = rel.split("/")[-1]
    ext = ""
    if "." in name:
        base, ext = name.rsplit(".", 1)
        ext = "." + ext
    else:
        base = name
    base = fix(base)
    prefix = "Отчет"
    for p in ("Отчет", "План", "Протокол", "Справка"):
        if base.startswith(p + "_"):
            prefix = p
            base = base[len(p) + 1:]
            break
    base = re.sub(r"^_+", "", base)
    base = re.sub(r"^[0-9]+(\.[0-9]+)*_+", "", base)
    base = base.strip("_")
    if not base:
        base = "Описание"
    return f"{prefix}_{new_id}_{num}.{m}_{base}{ext}"
```

```python
def history_md(task, tid, m):

def inject_css(text):
    if ".project {" in text:
        return text
    if "</style>" in text:
        return text.replace("</style>", CSS + "</style>", 1)
    if "</head>" in text:
        return text.replace("</head>", "<style>" + CSS + "</style>\n</head>", 1)
    return text


def inject_title(text, tid, m):
    if f"ID {tid}" in (re.search(r"<title>(.*?)</title>", text, re.S).group(1) if re.search(r"<title>(.*?)</title>", text, re.S) else ""):
        return text
    return re.sub(r"<title>(.*?)</title>",
                  lambda mm: f"<title>{mm.group(1)} | ID {tid} · Этап {tid}.{m}</title>",
                  text, count=1, flags=re.S)


def process_html(text, pfull, pid, tid, num, m, task):
    text = inject_css(text)
    text = inject_title(text, tid, m)
    top = identity_html(pfull, pid, tid, num, m)
    mbody = re.search(r"<body[^>]*>", text)
    if mbody:
        text = text[:mbody.end()] + "\n" + top + text[mbody.end():]
    else:
        mh1 = re.search(r"</h1>", text)
        if mh1:
            text = text[:mh1.end()] + "\n" + top + text[mh1.end():]
        else:
            text = top + text
    hist = history_html(task, tid, m)
    block = f"<!-- HISTORY:START -->\n{hist}\n<!-- HISTORY:END -->"
    if "<!-- HISTORY:START -->" in text:
        text = re.sub(r"<!-- HISTORY:START -->.*?<!-- HISTORY:END -->", block, text, count=1, flags=re.S)
    bottom = identity_html(pfull, pid, tid, num, m)
    if "</body>" in text:
        idx = text.rfind("</body>")
        text = text[:idx] + "\n" + bottom + block + "\n" + text[idx:]
    else:
        text = text + "\n" + bottom + block
    return text
```

## 15. Правила формирования отчёта API-методов маркетплейса

> Версия: 1.0 (2026-07-10) · Источник: анализ `Отчёт_API_Методы_Ozon_Основная_vs_Внедряемая.md`

### 15.1. Источники данных

Для каждого МП проверяются **4 группы источников**:

#### 15.1.1. Код базовой поставки (Основная)

| Что | Где | Что ищется |
|-----|-----|-----------|
| ObjectModule.bsl | `DataProcessors/<Префикс>_{MP}_ИнтеграцияС{Сервис}/Ext/ObjectModule.bsl` | `Метод = "vX/..."` |
| CommonModule (если есть) | `CommonModules/<Префикс>_{MP}_ИнтеграцияС{Сервис}/Ext/Module.bsl` | `Метод = "vX/..."` |

#### 15.1.2. Код поставки внедряемой конфигурации (Внедряемая)

| Что | Где | Что ищется |
|-----|-----|-----------|
| CommonModule.bsl | `CommonModules/<Префикс>_{MP}_ИнтеграцияС{Сервис}/Ext/Module.bsl` | `Метод = "vX/..."` |
| ObjectModule.bsl | `DataProcessors/<Префикс>_{MP}_ИнтеграцияС{Сервис}/Ext/ObjectModule.bsl` | `Метод = "vX/..."` |

> **Важно:** В Внедряемая CM и OM **дублируют** друг друга (lockstep). Проверка делается раздельно, чтобы зафиксировать расхождения в версиях API между CM и OM (например, CM использует v6, а OM — v5).

#### 15.1.3. Тестовое расширение базовой поставки (ТестОсновной)

| Что | Где | Что ищется |
|-----|-----|-----------|
| Переопределяемый модуль | `CommonModules/<Префикс>_UT_ИнтеграцииССервисами{MP}Переопределяемый/Ext/Module.bsl` | Строки эндпоинтов `"vX/..."` в функциях-заглушках/моках |
| Макеты-фикстуры (JSON) | `CommonTemplates/<Префикс>_{MP}_JSON_*` | Имена макетов содержат эндпоинты |

> **Архитектура ТестОсновной:** макеты хранятся в CommonTemplates (плоская структура, ~504 шт), моки — в переопределяемых модулях.

#### 15.1.4. Тестовое расширение поставки внедряемой конфигурации (ТестВнедряемой)

| Что | Где | Что ищется |
|-----|-----|-----------|
| ManagerModule.bsl | `DataProcessors/<Префикс>_UT_{MP}_ИнтеграцияС{Сервис}/Ext/ManagerModule.bsl` | Строки эндпоинтов `"vX/..."` в моках |
| ObjectModule.bsl | `DataProcessors/<Префикс>_UT_{MP}_ИнтеграцияС{Сервис}/Ext/ObjectModule.bsl` | Дополнительные моки |
| Макеты внутри обработки | `DataProcessors/<Префикс>_UT_{MP}_.../Templates/` | Имена макетов |

> **Архитектура ТестВнедряемой:** макеты хранятся внутри DataProcessors по каждому МП (модульная структура, 24+ обработок).

### 15.2. Методология проверки

#### Поиск эндпоинтов в коде
Для каждого BSL-файла ищутся строки вида `Метод = "v1/product/list";`. Результат: список уникальных API-эндпоинтов с отметкой, в каком модуле найден (CM или OM), и строкой.

#### Статус активности

| Признак | Статус | Обозначение в таблице |
|---------|--------|----------------------|
| Код активен, есть HTTP-вызов | Активен | ✅ |
| Код закомментирован (`// Метод = "..."` или `// код из базовой конфигурации...`) | Закомментирован | `✅ (коммент.)` |
| Только URL в строке-комментарии | Неактивен | `✅ (коммент.)` |

#### Определение статуса сравнения

| Статус | Условие | Символ |
|--------|--------|--------|
| **Совпадает** | Один и тот же эндпоинт и версия в Основная и Внедряемая | ✅ Совпадает |
| **Перенесено** | Есть в Основная, есть в Внедряемая, но только в CM (не в OM) или наоборот | 🔵 Перенесено |
| **Разные версии** | Один эндпоинт, но разные версии API (v1 vs v2, v3 vs v2) | ⚠️ Разные версии |
| **Неактивен** | Закомментирован в обоих расширениях | 💤 Неактивен |
| **Отсутствует** | Есть в Основная, отсутствует в Внедряемая (реально) | 🔴 Отсутствует |

#### Определение покрытия тестами
Эндпоинт считается **покрытым тестами**, если:
- В ТестОсновной: строка эндпоинта встречается в переопределяемом модуле (функция-заглушка возвращает JSON-макет)
- В ТестВнедряемой: строка эндпоинта встречается в ManagerModule.bsl (мокито-перехват)

> **Не считается покрытием:** простое наличие макета с похожим именем без явной привязки к эндпоинту в коде теста.

#### Сравнение макетов (колонка «Макет внедряемой = основной»)
Сравнивается **содержимое** макетов (файлы Template.txt/Template.xml) между ТестВнедряемой и ТестОсновной:

| Значение | Условие |
|----------|---------|
| `✅ да` | Файлы идентичны побайтово (`fc /b` = 0 различий) |
| `частично` | Идентичны не все — есть различия |
| `нет` | Макеты существуют, но различаются |
| `—` | Макетов нет ни в одном из тестовых расширений, или эндпоинт не покрыт тестами |

> **Важно:** сравнивается только содержимое (Template.txt), а не логика доступа к макетам (`ПолучитьМакет` vs `ПолучитьОбщийМакет`).

| 7 | `Перенесено` | ✅ если эндпоинт перенесён из базовой в внедряемой конфигурации; — если не требовался |
| 8 | `Внедряемая: CM` | Поиск в CommonModule внедряемой конфигурации |
| 9 | `Внедряемая: OM` | Поиск в ObjectModule внедряемой конфигурации |
| 10 | `ТестВнедряемой` | Поиск в ManagerModule.bsl ТестВнедряемой |
| 11 | `ТестОсновной` | Поиск в переопределяемом модуле ТестОсновной |
| 12 | `Макет внедряемой = основной` | Сравнение Template.txt |
| 13 | `Версия API` | Из строки эндпоинта (v1/v2/v3/...) |

### 15.4. Дополнительные таблицы отчёта

- **Итого** — сводка по статусам: Совпадает / Перенесено / Неактивен / Разные версии — с количеством и процентом
- **Сводка (метрики)** — `Показатель | Основная | Внедряемая (было) | Внедряемая (стало)`: записи макета `ВерсииМетодовAPI`, функции CM/OM, уникальные эндпоинты, процент покрытия
- **Новые функции** — добавленные в Внедряемая относительно предыдущей ревизии (CM и OM раздельно)
- **Таблица из макета ВерсииМетодовAPI** — для Основная и Внедряемая раздельно: метод (функция), версия API, эндпоинт, тип запроса
- **Сравнение API-эндпоинтов** — уникальные Основная, отсутствующие в Внедряемая; уникальные Внедряемая, отсутствующие в Основная
- **Различия версий API** — эндпоинт | версия в Основная | версия в Внедряемая | расхождение
- **Функциональные области** — 🔴 Критично (полностью отсутствующие блоки), 🟡 Частично реализовано, 🟢 Присутствует в обоих
- **Статистика покрытия** — по макету ВерсииМетодовAPI, по реальным вызовам, вновь перенесённые, неактивные в обоих, с разными версиями
- **Выводы** — нумерованный список ключевых выводов (10+ пунктов)

### 15.5. Ключевые отличия для разных МП

**Ozon:** только GET-запросы; единый префикс `vX/...`; CM и OM дублируют друг друга (lockstep); макет `ВерсииМетодовAPI` очищен (0 записей).

**Wildberries (WB):** GET + POST + PUT + PATCH + DELETE; множественные API-группы `api/vX/`, `content/vX/`, `card/`, `public/`; JSON-RPC для карточек товаров; разные домены: `api-seller.wildberries.ru`, `content-api.wildberries.ru`, `card.wildberries.ru`.

**Яндекс.Маркет (ЯМ):** OAuth 2.0 авторизация; разные домены для разных API-групп; GET + POST + PUT + PATCH.

### 15.6. Порядок выполнения

1. Найти код базовой поставки (`Основная`) — собрать эндпоинты
2. Найти код поставки внедряемой конфигурации (Внедряемая) — собрать эндпоинты из CM и OM раздельно
3. Найти тесты базовой поставки (ТестОсновной) — собрать покрытые эндпоинты
4. Найти тесты поставки внедряемой конфигурации (ТестВнедряемой) — собрать покрытые эндпоинты
5. Объединить все эндпоинты в сводную таблицу, отсортировать по алфавиту
6. Для каждого эндпоинта заполнить все 13 колонок
7. Сравнить макеты ТестВнедряемой и ТестОсновной (для колонки 12) — только если покрыто обоими
8. Построить итоговую статистику и выводы
